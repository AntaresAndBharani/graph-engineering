# Changelog

All notable changes to the Graph Engineering Agentic SDLC architecture will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added
- Added **Reviewer Autonomous Merge Conflict Resolution & Direct Auto-Merge (`orchestrator/nodes/reviewer.py`, `tests/test_nodes.py`)**: Equips the Reviewer node with a seamless CI verification, autonomous merge conflict resolution, and immediate merge execution pipeline. The Reviewer checks remote CI status, and for approved green PRs with merge conflicts, autonomously rebases against `origin/main`, resolves conflict markers with the AI conflict resolver, verifies local unit test suites (`pytest -v`), and executes immediate auto-merge into `main` without leaving PRs stalled in the queue. CI failures and unresolvable conflicts transition cleanly to `needs-refactor` for autonomous DevTest remediation.
- Added **Token Usage Ledger & Rolling Window StateManager API (`orchestrator/db.py`, `tests/test_db.py`)**: Implemented the `token_usage_events` SQLite WAL persistence schema and high-performance indices (`idx_token_usage_harness_time`, `idx_token_usage_project_node`) alongside asynchronous `StateManager` ledger methods: `record_token_usage_event`, `get_window_token_usage` (strict UTC rolling-window token sum), `get_usage_breakdown` (per-project and per-node token aggregations), and `get_token_usage_events`, establishing the zero-timezone-drift state foundation for multi-project global harness quota gating (Issue #52, Parent #44).
- Added **SDLC Memory Layer & Poller Synchronization (`orchestrator/poller.py`, `orchestrator/db.py`, `tests/test_poller.py`, `tests/test_db.py`)**: Equips the zero-token GitHub poller with background SDLC item synchronization (`poll_project_sdlc_items`, `sync_project_sdlc_items`). Automatically correlates open issues with linked PR numbers via branch names (`headRefName`), PR titles, and bodies, persisting them to the SQLite `sdlc_items` table with non-blocking, best-effort error handling (Issue #37).
- Added **Harness Anomaly & SLA Event Recording (`orchestrator/harness.py`, `orchestrator/db.py`, `tests/test_harness.py`)**: Configured `AsyncHarnessAdapter` to record categorized anomaly events (`record_anomaly_event`) in SQLite on transient API errors (classified as `http_503`, `http_429`, `http_502`, `http_504`, `connection_reset`) and execution SLA timeouts (`sla_violation`), with 24-hour cutoff querying (`get_recent_anomalies`) and non-blocking failure tolerance (Issue #37).
- Added **Layer 3 Pipeline Node Blackboard Producer Wiring (`orchestrator/nodes/*`)**: Wired all Application Pipeline Nodes (`architect.py`, `devtest.py`, `reviewer.py`, `supervisor.py`, `bau.py`) as active producers into the Decoupled Artifact Blackboard (`StateManager.sync_project_sdlc_items` and `StateManager.record_anomaly_event`). Scanned issues, decomposed subtasks, implementation PRs, and auto-merged pull requests are now continuously synchronized into `sdlc_items`, while harness failures, safety violations, merge conflicts, and CI check failures are recorded in `anomaly_events` for real-time presentation consumption in `SDLCProgressWidget` and `AnomalyAlertsWidget` (PR #42 remediation).
- Added **Multi-Pane Dashboard Layout & Reactive Project Selection (`orchestrator/ui/dashboard.py`)**: Restructured `DashboardApp` with a 50/50 horizontal bottom split hosting `SDLCProgressWidget` on the bottom-left and `TabbedContent` with "Logs" (`RichLog`) and "Alerts (24h)" (`AnomalyAlertsWidget`) on the bottom-right. Wired `@on(DataTable.RowHighlighted)` on `#projects_table` for reactive instant filtering of active SDLC items and recent anomalies from SQLite upon row navigation (Issue #39).
- Added **`SDLCProgressWidget` and `AnomalyAlertsWidget` for Textual TUI Dashboard (`orchestrator/ui/widgets.py`, `orchestrator/ui/__init__.py`)**: Implemented read-only Textual `DataTable` widgets rendering active SDLC items (issues/subtasks/PRs with columns `[ID | Title | Status/Label | Linked PR]`) and 24-hour anomaly/retry alerts (columns `[Timestamp | Node | Error Type | Error Message]`) directly from local SQLite persistence, featuring non-blocking asynchronous queries, graceful empty states, and dynamic project switching without event loop lag (Issue #38).
- Added **SDLC Items & Anomaly Events SQLite Memory Layer (`orchestrator/db.py`)**: Added `sdlc_items` and `anomaly_events` tables (indexed by `idx_anomalies_project_time`) along with asynchronous StateManager helper methods `sync_project_sdlc_items`, `get_sdlc_items`, `record_anomaly_event`, and `get_recent_anomalies` enforcing the Zero-HTTP UI architecture (Issue #36, #38).
- Added **Comprehensive Widget & SDLC Memory Test Suite (`tests/test_dashboard.py`, `tests/test_db.py`)**: Added BDD Given/When/Then test coverage for SDLC item rendering, empty-state rows, 24h anomaly time-window filtering and pruning boundary, multi-project isolation, and non-blocking Textual async execution (Issue #38).
- Added **Graceful TUI Dashboard Teardown & Task Draining Protocol (`orchestrator/ui/dashboard.py`, `orchestrator/harness.py`, `tests/test_dashboard.py`)**: Implemented a two-stage safe shutdown mechanism for the Textual TUI dashboard (`orchestrator watch`). On the first `Q` keypress (or `SIGINT`), if running jobs exist, the dashboard enters `DRAINING` mode, notifies the operator, requests daemon halt so no new passes start, and asynchronously waits for running agent tasks (harness processes, test runs, git commits) to finish cleanly with a 30s safety timeout. A second `Q` keypress triggers an immediate emergency force quit (`force=True`) with active subprocess termination. Prevents dirty git working trees, corrupted commits, and deadlocked state locks.
- Added **Autonomous `needs-refactor` PR Remediation Loop (`orchestrator/nodes/devtest.py`, `tests/test_devtest_refactor.py`)**: Equips the DevTest Node with proactive PR remediation logic (`_remediate_refactor_pr`). DevTest queries for open PRs labeled `needs-refactor`, fetches the Architect's specific code review critique from PR comments/reviews, checks out the PR branch, dispatches the AI harness with structured architectural feedback, verifies local unit tests pass, commits/pushes the refactor, and transitions the PR back to `needs-architect-review` for automated re-evaluation without human intervention.
- Added **Transient Upstream Error Retry Engine (`orchestrator/harness.py`, `orchestrator/config.py`)**: Equips `AsyncHarnessAdapter` with an automatic, in-memory retry mechanism using exponential backoff and randomized jitter to recover transparently from transient AI gateway dropouts (`503 UNAVAILABLE`, `429 RESOURCE_EXHAUSTED`, `502/504 Bad Gateway/Timeout`, connection resets, rate limits, quota exceeded). Configured via `HarnessRetryConfig` and integrated into `HarnessConfig` and `templates/config.example.yaml` (Issue #33).
- Added **Comprehensive Retry Engine Test Suite (`tests/test_harness.py`, `tests/test_config.py`)**: Unit and integration tests covering transient 503 recovery on attempt 2, immediate 401 fail-fast, retry exhaustion after 3 attempts, backoff delay jitter bounds, and configuration validation (Issue #33).
- Added **Orphaned Ghost Lock Auto-Reclamation (`orchestrator/db.py`, `orchestrator/cli.py`)**: `StateManager.cleanup_orphaned_running_jobs()` automatically identifies and reclaims leftover `RUNNING` locks on daemon registration and single-pass CLI invocations, eliminating 30-minute deadlock freezes caused by interrupted or restarted daemon processes.
- Added **Retry-Aware Lock TTL Budgeting (`orchestrator/nodes/architect.py`, `orchestrator/nodes/devtest.py`)**: Sized execution lock TTLs dynamically based on `timeout_minutes * (1 + max_retries) + 5`, ensuring locks do not prematurely expire while `AsyncHarnessAdapter` executes exponential backoff across retries.
- Added **Live Real-Time Stream Listeners in `AsyncHarnessAdapter` (`orchestrator/harness.py`, `orchestrator/ui/dashboard.py`)**: Implemented `register_stream_listener` / `unregister_stream_listener` class methods in `AsyncHarnessAdapter`, piping live subprocess output lines directly into the TUI dashboard's `RichLog` widget so operators observe real-time agent progression without perceived freezing.
- Added **Global UTF-8 Output Standard (`orchestrator/__init__.py`)**: Reconfigured `sys.stdout` and `sys.stderr` to UTF-8 on package import to prevent Windows `cp1252` encoding errors when handling emojis and unicode text in issue bodies and logs.
- Added **Textual TUI Observability Dashboard for `orchestrator watch` (`orchestrator/ui/dashboard.py`)**: Implemented `DashboardApp` featuring real-time, non-blocking project status monitoring via `DataTable` (sorted alphabetically by project name with columns `[Project Name | Repository | Active Node | Status | Last Updated | Locks/Anomalies]`), periodic 2s async refresh, and graceful teardown (`Q` key and `SIGINT`) terminating active harness subprocesses and unregistering the daemon PID from `state.db` (Issue #21, #22, #25, #26).
- Added **Bounded & Filtered Log Stream (`orchestrator/logging.py`)**: Implemented `TextualLogHandler` backed by a bounded `collections.deque(maxlen=1000)` buffer attached to the root `orchestrator` logger, automatically filtering out verbose per-node agent harness traces while streaming live daemon events to the UI's `RichLog` widget (Issue #23).
- Added **Headless Auto-Detection & CLI Options (`orchestrator/cli.py`)**: Enhanced `watch_command` with `--dashboard/--no-dashboard` and `--headless` flags, automatically falling back to standard asynchronous polling and linear stdout logging when stdout is not a TTY (CI/CD environments) with zero TUI overhead and lazy import gating (Issue #24).
- Added **Comprehensive Dashboard Test Suite & Documentation Sync (`tests/test_dashboard.py`, `tests/test_cli.py`, `docs/node-cli.md`, `.graph/architecture.md`)**: Unit and integration tests covering bounded log buffering, node-trace filtering, alphabetical table sorting, headless fallback, and clean signal teardown (Issue #27).
- Added **Blackboard Gherkin AC Ingestion for Architect Triage (`orchestrator/nodes/architect.py`)**: The Architect node queries `po_tracking` on the Decoupled Artifact Blackboard (`get_po_tracking`) and incorporates pre-approved Gherkin Acceptance Criteria directly into the triage and INVEST decomposition context, avoiding redundant requirement re-derivation.
- Added **Automated Gherkin Acceptance Criteria Enrichment & Promotion (`orchestrator/nodes/supervisor.py`)**: Implemented automated functional requirement evaluation via `gemini-3.7-flash-low`, Gherkin Given/When/Then Acceptance Criteria generation and issue body enrichment, label promotion from `needs-po-review` to `needs-triage`, human clarification loop guarding with structured feedback comments, and `PO_APPROVED` status synchronization on the SQLite WAL Blackboard (`po_tracking`).
- Added **SHA-256 Hash Tracking & Zero-Token Skip Gating (`orchestrator/nodes/supervisor.py`)**: Computes deterministic SHA-256 digests over `(title + "\n" + body)` for issues evaluated by the Supervisor PO-Proxy, short-circuiting unchanged issues in `NEEDS_HUMAN_CLARIFICATION` state without LLM harness invocations (Issue #11).
- Added comprehensive unit and integration test coverage (`tests/test_supervisor_po.py`, `tests/test_db.py`) verifying Given/When/Then acceptance criteria, model configuration, label transitions, hash-based skipping, schema column verification, composite primary keys, and zero-token assertion verification.
- Added **Supervisor PO-Proxy CLI Inspection & Evaluation (`orchestrator supervisor evaluate` & `orchestrator supervisor status`)**: Exposes interactive and dry-run (`--dry-run`) evaluation commands for issues labeled `needs-po-review` with Gherkin acceptance criteria generation, SHA-256 hash gating, and persistent `po_tracking` Blackboard status reporting.
- Added **Decoupled Blackboard `po_tracking` Table (`orchestrator/db.py`)**: Persistent SQLite WAL table and helper methods (`upsert_po_tracking`, `get_po_tracking`, `delete_po_tracking`, `list_po_trackings`) for cross-node PO readiness context.
- Implemented the **Decoupled, Agnostic Multi-Agent Orchestrator CLI (`graph-orchestrator`)** in Python (`pyproject.toml`, `orchestrator/`), decoupling workflow execution and state from target application repositories.
- Added **Zero-Token Idle Polling**: GitHub issues/PRs are queried deterministically using batched GitHub CLI / GraphQL queries, spending zero AI tokens during idle periods.
- Added **Agnostic AI CLI Harness Adapter Pattern** (`orchestrator/harness.py`): Supports interchangeable execution across `claude` (Claude Code), `agy` (Antigravity CLI), `devin`, or custom runners via declarative configuration (`config.yaml`).
- Added **Model Level of Effort / Reasoning Configuration**: Supported via `effort_flag` in `HarnessConfig` (e.g. `--effort low|medium|high|max` for Claude), embedded model naming for Antigravity (`gemini-3.7-flash-thinking`), and `effort` specifications in `NodeConfig`.
- Implemented **Native OAuth Subscription Token Support**: Harnesses seamlessly inherit user profile paths and OAuth credentials, utilizing developers' active hired subscriptions rather than requiring raw API tokens.
- Implemented **Consistency Supervisor Node (Node 0)** (`orchestrator/nodes/supervisor.py`): Scheduled/startup self-healing node with zero-token anomaly filtering (detects merge conflicts, orphaned PRs, stuck locks) that auto-resolves state or escalates to `needs-po-review`.
- Implemented **Architect Node (Node 1)** (`orchestrator/nodes/architect.py`): Evaluates `needs-triage` issues, decomposes stories into INVEST/3-amigos subtasks with Gherkin criteria, and provisions child issues labeled `ready-for-dev`.
- Implemented **3AmigosDevTest Node (Node 2)** (`orchestrator/nodes/devtest.py`): Sanitizes workspace with strict remote-matching git safety checks, generates code and unit/integration tests, verifies test pass and non-empty git diff, opens PRs labeled `needs-architect-review`, and auto-merges when approved.
- Implemented **State Locking & Concurrency Engine** (`orchestrator/db.py`): Asynchronous SQLite database (`state.db`) configured with Write-Ahead Logging (WAL) and TTL lock expiration to prevent duplicate executions and recover from daemon restarts.
- Implemented **Structured Logging & ANSI Stripping** (`orchestrator/logging.py`): Dedicated per-project/per-node log hierarchies (`~/.config/orchestrator/logs/<project>/<node>/`) with active regex ANSI filtering and automatic rotation.
- Added **Automated Label Housekeeping** (`orchestrator/housekeeping.py`): Automatic idempotent provisioning of workflow taxonomy labels across all registered repositories using `gh label create --force`.
- Added **CLI Command Suite** (`orchestrator/cli.py`): Full Typer + Rich CLI supporting `run`, `watch` (live dashboard), `list`, `doctor` (with optional `--sync-labels`), `init`, `labels` (taxonomy sync/list), `ingest`, `clean`, and `logs`.
